🚨 Disaster Recovery Console

The complete, guided recovery path when a Supabase project is lost, paused beyond rescue, or must be replaced — restoring every exam, question, roster, result and setting from the school's Google Drive backups into a brand-new free-tier project. Follow the steps in order; every step verifies itself before the next unlocks.

📖 When you need this page — the exact scenario it solves

A school's Supabase project became inactive / paused / unreachable — or the account holding it was lost — and it can no longer be unpaused or accessed. The school was careless about logins, but they were never careless about their data: the platform had been syncing full backup envelopes to their own Google Drive. This console re-builds their entire platform on a fresh free Supabase project, linked to that same Google Drive account, in seven verified steps — no data lost, no paid tools, finished in roughly 15 minutes.

✅ What is recovered
  • Every exam + full question bank (all 20 types, options, keys, explanations)
  • Student rosters (per teacher, with IDs and classes)
  • All candidate results incl. answers, scores, times, integrity logs
  • Platform settings, site license and heartbeat state
  • Archive-vault backups (if they were exported to Drive)
⚠️ What is honestly NOT recovered
  • Teacher/admin login accounts (Supabase Auth users live inside the lost project — see Step 6 for the 2-minute re-invite)
  • Face-gate proctor photos stored only in the old database
  • Changes made after the newest Drive backup — which is why auto-sync matters

🔗 Connect the school's Google Drive (the previous backup account)

Sign in with the SAME Google account the old platform used for backups (the one whose Drive contains the HMG_CBT_Backups folder). The Drive client uses the drive.file scope — it can only see files this platform created.

STEP 2

🆕 Create & prepare the fresh Supabase project

  1. Go to supabase.com/dashboard → New project → choose the FREE plan, a strong database password, and a region close to the school.
  2. Open SQL Editor → New query.
  3. Open database/complete-schema.sql (shipped with this platform and inside every backup ZIP), copy all of it, paste, and Run. It is idempotent — it installs all 10 tables, 40+ RPCs, security policies, the archive-vault bucket, the heartbeat system and starter rows in one pass. Running it twice is harmless.
  4. Go to Project Settings → API and copy the Project URL and the anon public key (starts with eyJ…). Paste them below.
STEP 3

📦 Choose the backup to restore

Pick from the Drive backups listed in Step 1. The newest is preselected. Inspect its contents before committing — counts come from the envelope's own metadata.

STEP 4

🧪 Dry-run the restore (nothing is written yet)

The engine replays the backup against the new project and reports exactly what would happen: every insert, update and skip — with reasons. Review it; only a plan you approve moves to Step 5.

STEP 5

🚀 Execute the restore & verify

Writes the approved plan into the new project, then re-counts every table in the live database and compares it against the envelope — a green check means the rows are really there, not assumed.

STEP 6

🔁 Point the platform at the new project permanently

  1. Redeploy with new credentials — either regenerate the platform ZIP from the Generator (paste the new URL + anon key in step 3 of the wizard), or edit assets/js/app.js: replace the SB_URL and SB_KEY constants with the values from Step 2, commit, and redeploy (Vercel/GitHub Pages).
  2. Re-create staff logins — Supabase Auth users cannot be migrated from a lost project. Have each teacher/admin sign up again on the new deployment (Authentication → Users shows them arriving), then an existing admin (the first account becomes super_admin automatically) approves them in Roles & Status. Their exams and results re-attach automatically because data is matched by exam code and student ID, not by login.
  3. Re-link Google Drive on the new deployment — Settings → Google Drive Cloud Sync → paste the same Client ID (add the new deployment URL to the Google Cloud authorized origins) → Authorize. The next auto-backup lands in the same HMG_CBT_Backups folder.
STEP 7

🛡️ Re-arm the free-tier protection (≈7 minutes, once)

A fresh project starts its 7-day inactivity clock immediately. Full instructions live in SUPABASE_FREE_TIER_PROTECTION.md; the essentials:

  1. Add repository secrets SUPABASE_URL + SUPABASE_ANON_KEY (new values) and set workflow permissions to Read and write — this arms the twice-weekly verified heartbeat.
  2. Add SUPABASE_ACCESS_TOKEN + SUPABASE_PROJECT_REF to arm the daily auto-restore watchdog.
  3. Point an UptimeRobot monitor at /api/keepalive for an independent 24/7 ping.
  4. Run Platform Health → Write Heartbeat Now and confirm the timestamp proof, then schedule the first backup to Drive immediately.

🧭 Every circumstance, covered

Drive has several backups — which one? The newest by modified date is preselected; older ones remain in the list for point-in-time recovery.

The newest backup is weeks old. Restore it anyway — everything after the backup date is unrecoverable, which is exactly why the platform nags when auto-sync is off. After recovery, enable auto-sync.

The new project already has some data. The restore upserts: exams match by their unique code (updated, never duplicated), students by (teacher, student ID), results are re-inserted without touching existing rows. Nothing is deleted.

An exam code collides with different content. The dry-run flags it as an update with counts — you see it before anything is written.

Teacher logins can't be restored. Auth users belong to Supabase, not to your data. Step 6 re-invites staff in two minutes; data re-attaches by code/ID matching.

No Google sign-in on this device. Use the Step 1 file fallback with any previously downloaded envelope JSON.

Old backup format (v10.0 legacy envelope). The engine auto-converts legacy envelopes; the plan will say so.

Restore interrupted mid-way. Re-run it — every phase is idempotent (upserts + duplicate-tolerant inserts), so a second pass completes what the first started.

Need to KEEP the old project too? This same console is a pure migration tool: the old project is never contacted after Step 2.
