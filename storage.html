📦 Storage Manager

Keep the free-tier database (≈500 MB) tiny forever: real table sizes, an Archive Vault that moves cold rows into the separate 1 GB File Storage, and archive-first purging that can never run before its archive upload has succeeded.

🗄️ What is this page?

Supabase's free tier gives every project ≈500 MB of database AND a separate 1 GB of File Storage. This page shows exactly what consumes the database (real row counts and physical sizes from Postgres statistics), recommends what can be archived, and moves old rows — as portable JSON snapshots — into the private archive-vault bucket before purging them from the database. Archived data can be browsed, downloaded and restored back into the database at any time.

📦 Archive Vault — move old rows into the 1 GB File Storage

Pick a table and a cutoff date. The manager fetches the old rows, uploads them as a JSON snapshot to the private archive-vault bucket, verifies the upload, and only then purges them from the database (proof of the archive path is required by the purge RPC). Every step is audit-logged.
